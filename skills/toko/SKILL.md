# Toko tokens

Toko is a web app where people make a color palette, surfaces, shadows and a type scale. It exports two files:

- `tokens.css`: every value, for light and dark, as CSS custom properties. The source of truth.
- `tailwind.css`: for Tailwind v4 only. An `@theme inline` block that turns those properties into utilities (`bg-surface`, `text-text-muted`, `shadow-md`, `text-title-3`). It imports `./tokens.css`, so the two files sit in the same folder.

Both start with `/* Generated by Toko. Edit the inputs, not this file. */`. Search for that line to find them. They are generated, so never edit them: to change a value, change the palette in Toko, then bring in the new files. The project adapts to the tokens, not the other way round. A `toko.json` at the project root means the project is linked to a palette saved in Toko: then the Toko CLI (`npx @layoutinc/toko`) writes the files into the folder named by `out`, and `toko pull` brings in changes; nobody copies files by hand.

The person you're helping may not be a developer. Keep them informed in plain words and keep going on your own wherever a sensible default exists.

## Pick the job

- **Install**: there's no `<!-- toko:start -->` section in AGENTS.md or CLAUDE.md yet. Do steps 1–9.
- **Sync**: there's a `toko.json`, or the user asks to change, pull or push the palette. Read [sync.md](references/sync.md); if the pull lists follow-ups, also do steps 6–9.
- **Update**: the section exists, there's no `toko.json`, and the user brought new files or asks to re-sync. Read [update.md](references/update.md), then do steps 6–9.
- **Check**: the user only asks whether the code uses the tokens, whatever state the install is in. Run the checks from step 8, report what they found in plain words, and change nothing.

## Steps

1. **Look before you change anything.** Work out the framework, the global stylesheet, the Tailwind version, shadcn, how dark mode works today, and whether Toko was installed before. See [detect.md](references/detect.md). Guessing here causes most broken installs.
2. **Tell the user the plan** in 3–5 short lines of plain words, e.g. "Your app uses Tailwind and shadcn and has a dark-mode switch. I'll connect them to your Toko palette, switch the text to your Toko type, and replace the colors typed in by hand." Then carry on without waiting. Pointing theme variables at the tokens and removing the old dark color block is part of the job; don't ask about it. Stop and ask only before deleting the user's own files, or when a choice would change how the app looks in a way the tokens don't decide, like its layout. If the project uses git, note the current commit so the report can say how to undo; don't commit for the user.
3. **Install the files**, with the Toko CLI where it can run, and import them exactly once. See [install.md](references/install.md).
4. **Make light and dark follow the tokens.** See [dark-mode.md](references/dark-mode.md).
5. **Connect what's already there.** If the project uses shadcn or has its own theme variables, point them at Toko's tokens. See [shadcn.md](references/shadcn.md). Put `data-surface` on cards, menus, dialogs and navigation. See [surfaces.md](references/surfaces.md).
6. **Replace hard-coded values** with the token whose purpose matches, in small batches. See [migrate.md](references/migrate.md).
7. **Leave rules for later sessions**: write the Toko section into AGENTS.md. See [agents-md.md](references/agents-md.md).
8. **Check your work** with the checks below, then build.
9. **Report back** in plain words. See [report.md](references/report.md).

## Checks

With this skill installed, run its scripts from the project root. They live next to this file, usually in `.agents/skills/toko/scripts/` or `.claude/skills/toko/scripts/`. Both print JSON and never change files.

```bash
node .agents/skills/toko/scripts/inventory.mjs .   # every hard-coded color, shadow and font size, by file and line
node .agents/skills/toko/scripts/check.mjs .       # Toko files, imports, unknown variables and surfaces, leftovers, AGENTS.md, toko.json
```

`check.mjs` exits 0 when everything passes. With a `toko.json`, it also checks the files still match it; `npx @layoutinc/toko check` runs the same checks without the skill. When installing or updating, fix what it reports and run it again until it passes. A value you keep on purpose (a logo color, chart data) gets a `toko-keep` comment on its line, `/* toko-keep */` or `// toko-keep`, so both scripts skip it.

Without the scripts (for example when working from a pasted prompt, or in a sandbox that can't run Node), search instead:

- Toko files and how often they're imported: search for `Generated by Toko` and for `tokens.css` / `tailwind.css` in imports and `<link>` tags. Expect one import path.
- Leftover literals, outside the Toko files and lines marked `toko-keep`: `#[0-9a-fA-F]{3,8}\b`, `rgba?\(`, `hsla?\(`, `oklch\(`, `box-shadow:` and `font-size:` without `var(`, Tailwind palette classes like `bg-blue-500`, and arbitrary values like `bg-[#…]` or `text-[13px]`.
- Variables that no longer exist: every `var(--…)` used in the code should be declared in tokens.css or in the project's own CSS.

Then run the project's build or typecheck, and if you can, look at the app in light and in dark.

## Defaults when you're unsure

- Where the files go: next to the global stylesheet, in a `toko/` folder (`src/styles/toko/`, `app/toko/`).
- A color that could be two tokens: take the one that matches what the element *is* (text, border, main button), and list it under "worth a look" in the report.
- Tailwind's default palette: `tailwind.css` removes it (`--color-*: initial`) so only the palette's colors exist. Keep that and migrate the old classes. If the user insists on keeping Tailwind's colors, explain that it means changing the generated file, and put it in the report; don't do it silently.
- Fonts: the type scale is part of the palette, so load its font (Inter) and say so in the plan.
- Colors in images, logos, syntax themes and chart data: leave them, marked `toko-keep`.

## Never ship

- Edits inside `tokens.css`, `tailwind.css`, any file in toko.json's `out` folder, or toko.json's `lock`.
- A second import of the Toko files, or a copy of them in another folder.
- A value changed to the *nearest-looking* token instead of the one that matches the element's purpose.
- `dark:` color overrides or a separate dark color block next to the tokens. The tokens already switch.
- Restyling: new spacing, radius, layout or components. Only the values the tokens cover change.
- A second Toko section in AGENTS.md, or one still saying `<folder>`.

## Done when

- [ ] The Toko files are imported once, and the app builds.
- [ ] Light and dark both come from the tokens, including the app's own theme switch if it has one.
- [ ] Cards, menus, dialogs and navigation carry `data-surface`.
- [ ] No hard-coded colors, shadows or font sizes remain, except lines marked `toko-keep`, each listed in the report with the reason.
- [ ] AGENTS.md has exactly one Toko section, and CLAUDE.md points to it if the project has one.
- [ ] The user has a short report.
